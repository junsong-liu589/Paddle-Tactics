# 11 — 乒乓世界杯与比赛表现更新

## 产品范围

- 八位现有球员参加单败淘汰赛，抽签由浏览器随机生成并保存 seed，产出四分之一决赛、半决赛和决赛共七场签位。
- 开赛前选择纯观战或操控一名球员；参赛者先选择球员与球拍配置，再抽签。其余球员由本地 AI 按现有球员能力风格从现有装备中选择配置。
- CPU 对 CPU 使用 BO7；玩家对 AI 使用现有比赛页面和规则，使用 BO3。每场比赛仍由现有 `game-core` 判定每一局，不新增或改写 Candidate V4 回合规则。
- 观战按局揭示比分与每局最终小分，自动进入下一场直至产生冠军。玩家可高亮支持对象；被淘汰后可继续观看余下赛事或离开。
- 比赛赛果只展示局分和最终小分，不播放每个回合的操作过程。

## 球员和比赛展示

- 八位现有球员各有一张前端 2D 卡通角色图；人物介绍保留现有配置与数值信息，并展示打法描述和配装预览。
- 六维图分别映射发球攻击/防守、反制攻击/防守、相持攻击/防守。维度值由当前装配对 `game-data` 能力的既有贡献计算，仅用于展示；图形半径按 3–13 分线性映射，3 分在中心、13 分到外圈，10 分占 70% 半径。图形缩放不修改球员或装备数据。
- 比赛中央展示双方角色和少量可复用的攻防动作、球轨迹与命中效果。动画只读取已公开阶段和比赛事件，不参与胜负判定，也不把隐藏加点展示给对手或观众。
- 插画是风格化生成素材；授权和发布核查状态见 `docs/10_LEGAL_ASSETS.md`。

## 架构和部署

世界杯签位、CPU 比赛、进度、支持者选择存放在用户浏览器 `localStorage`。CPU 使用项目内的 TypeScript AI 与 `game-core`，无需外部模型 API、账号、服务器或数据库；无按用户增长的 AI API 费用。静态构建照常输出 `apps/web/dist`，可部署到支持 SPA 回退的静态托管。

当前版本不提供多人跨设备同步、账号库存或远程观战。玩家与 AI 的真实交互对局仍通过既有浏览器内局部比赛；该模式免费且没有常驻后端。刷新中断的人类实时对局不属于持久恢复范围；已保存的赛事 bracket 可恢复并继续。

## 检查项

- `packages/game-core`：BO7 只允许世界杯显式 opt-in；既有默认 BO1/3/5 限制和单局规则不变。
- `apps/web/src/lib/world-cup.test.ts`：八人不重复签位、装备策略合法、六维数据和完整七场 CPU 淘汰赛。
- `e2e-web/local-preview.spec.ts`：现有本地 AI/同屏双人入口保留、世界杯观战和支持者高亮、参赛准备与六维介绍。
- 构建输出为静态资源；没有新增第三方运行服务、付费 API 或数据库迁移。
